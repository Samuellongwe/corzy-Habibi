# Cozy Habibi — Production Ordering System

This upgrades the supplied front-end sales prototype into a deployable restaurant operations system. The original prototype already had menu filtering, cart persistence, WhatsApp ordering, QR/table demo, loyalty demo and reservation requests; this build moves those workflows behind a real API and database. fileciteturn0file1L8-L16

## Included
- Express production server with Helmet, compression, CORS and rate limiting.
- SQLite database in WAL mode for menu, orders, order items, reservations, loyalty members and admin users.
- Server-side price calculation: clients submit product IDs/quantities; the server calculates totals from the database.
- Persistent orders with statuses: pending → confirmed → preparing → ready → completed/cancelled.
- Reservation management and status workflow.
- Loyalty member registration.
- Protected admin dashboard at `/admin`.
- QR table ordering using `?table=14` (for example, `https://your-domain/table?table=14`).
- Existing premium Cozy UI retained.
- WhatsApp notification remains available after the order is saved in the database.

## Run locally
1. Install Node.js 20+.
2. Copy `.env.example` to `.env`.
3. Set a strong `JWT_SECRET` (32+ characters) and `ADMIN_PASSWORD` (12+ characters).
4. Run `npm install`.
5. Run `npm run init-admin`.
6. Run `npm start`.
7. Open `http://localhost:3000`.
8. Admin: `http://localhost:3000/admin`.

## Production deployment
- Use HTTPS behind a reverse proxy/load balancer.
- Set `NODE_ENV=production`.
- Use a persistent volume for `DB_PATH` and back up the database.
- Set `CORS_ORIGIN` to the exact production origin.
- Replace demo menu prices and stock/menu data with Cozy-approved values before launch. The supplied prototype explicitly says its prices are placeholders. fileciteturn0file1L19-L25
- Replace external Unsplash image URLs with licensed Cozy-owned/approved images.
- Set the real WhatsApp number in `WHATSAPP_NUMBER` and wire it into the frontend if it differs from the supplied number.
- For multi-location/high-volume deployment, move the data layer to PostgreSQL and add a queue/worker for notifications.
- Add a payment provider only after the restaurant's merchant account and payment flow are approved; no payment credentials are hard-coded here.

## Important production boundary
This is a production-oriented application foundation, not a claim that payment, kitchen printer/POS integration, tax rules, inventory, refunds, backups, domain/DNS, monitoring and payment-provider credentials are already configured. Those require Cozy's operational decisions and credentials.
